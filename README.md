# Табель рабочего времени · 0.4.0

В проект входят веб-версия для ПК и мобильных браузеров, сервер и отдельный мобильный клиент на React Native для Android и iOS. Браузер и приложения используют одни и те же учётные записи и общую базу SQLite. Для работы с табелем нужна связь с сервером.

## Демо в браузере

Требуется Node.js 24. У сервера нет дополнительных npm-зависимостей.

```sh
node server.js --demo
```

Откройте http://127.0.0.1:3000 и выберите любую из пяти ролей. Данные демо хранятся в памяти и сбрасываются при остановке сервера. Для мобильного клиента используйте отдельный рабочий HTTPS-сервер и созданную учётную запись.

## Первый запуск с рабочей базой

В Linux или macOS создайте первого кадровика:

```bash
read -r -s -p 'Пароль кадровика (от 12 символов): ' tabel_password
printf '\n'
printf '%s' "$tabel_password" | node src/admin.js hr "Имя Фамилия"
unset tabel_password
node server.js
```

В Windows PowerShell:

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$secret = Read-Host "Пароль кадровика (от 12 символов)" -AsSecureString
[System.Net.NetworkCredential]::new('', $secret).Password | node src/admin.js hr "Имя Фамилия"
Remove-Variable secret
node server.js
```

Войдите в браузере под кадровиком. Добавьте объект, создайте руководителей и монтажников. Для каждого монтажника отметьте тех руководителей, которым доступен его табель. Назначения можно поменять в справочнике сотрудников через кнопку «Руководители». Мастера, прорабы и инженеры могут вести табели одних и тех же монтажников. Монтажник без назначений виден кадровику.

## Роли и закрытие месяца

| Роль | Доступ | Действия |
| --- | --- | --- |
| Монтажник | Собственные записи | Просмотр |
| Мастер, прораб, инженер | Назначенные монтажники | Просмотр, ввод и изменение записей открытого месяца, выгрузка Excel |
| Кадровик | Все монтажники | Действия руководителя, закрытие месяца. Создание учётных записей и особых дат. В браузере также изменение справочника «Праздники», назначение руководителей и добавление объектов |

Для сотрудника на одну дату предусмотрена одна запись. У рабочей смены один объект, время начала и конца, перерыв и отметка о переходе через полночь. Все часы ночной смены относятся к дате её начала. Доступны отпуск, больничный и выходной. Сохранённая запись сразу входит в месячный итог. Часы смены после вычета перерыва делятся на обычные (до 8 ч, ×1), первые 2 ч переработки (×1,5) и оставшуюся переработку (×2). В предпраздничный день норма составляет 7 ч. По субботам, воскресеньям и в праздники все отработанные часы отображаются в категории ×2. Явно заданный предпраздничный день имеет приоритет над правилом выходного. Разбивка видна в ячейках и итогах. Ранее закрытые месяцы сохраняют прежний расчёт.

### Праздники и выгрузка

В справочнике «Праздники» кадровик выбирает год и задаёт вид дня и его название. В базу однократно перенесены восемь праздничных дат из исходного проекта за 2026 год. Дополнительные даты и предпраздничные дни задаются в справочнике. Даты закрытого месяца защищены от изменений.

Кнопка «Выгрузить Excel» формирует таблицу за выбранный месяц по предоставленному образцу. На сотрудника приходится блок из пяти строк, у каждой категории есть формулы суммы часов и количества дней. Строка объекта использует цвета справочника. Комментарии добавляются как примечания к ячейкам и выводятся на лист «Комментарии», если они есть. Строка 22.00–06.00 сохранена в бланке. До согласования ночной надбавки часы ночной смены учитываются в общих категориях ×1, ×1,5 и ×2. Старый CSV по-прежнему доступен через `/api/export`.

Кадровик задаёт цвет при добавлении объекта и может поменять его в справочнике «Объекты». Цвет используется для ячеек смен этого объекта, включая прошлые периоды.

### Заполнение одинаковых смен

- В недельной сетке потяните за квадрат в нижнем углу заполненной ячейки вправо по датам или вниз по сотрудникам.
- Для выбора диапазона клавиатурой нажмите на этот квадрат. В карточке смены в веб-версии и мобильном клиенте есть кнопка «Заполнить диапазон».
- Копируются объект, вид записи, начало, конец, перерыв и признак ночной смены. Комментарий исходной смены не копируется, существующий комментарий в целевой ячейке сохраняется.
- Существующие записи заменяются после подтверждения. Заполнение действует в пределах открытого месяца и доступных пользователю сотрудников. При активном фильтре по объекту или статусу снимите его перед заполнением.

Кадровик видит количество записей, суммарное время и число сотрудников без записей, затем подтверждает закрытие. Приложение не считает отсутствие записи за конкретный день ошибкой: графики и нормы рабочих дней пока не заведены. Закрытие блокирует и создание, и изменение смен выбранного месяца. Система записывает, кто и когда его закрыл. При изменении табеля после открытия окна подтверждения кадровику нужно заново проверить итоги. Повторное открытие закрытого месяца через интерфейс пока не предусмотрено.

Новая база создаётся автоматически. Если вы использовали локальную SQLite-базу версии 0.1.0, её идентификаторы, записи и история сохраняются при обновлении. Сохранённые черновики и записи на проверке переходят в учтённые, прежнее назначение мастера переносится в список руководителей.

## Развёртывание

Нужен сервер или контейнерный хостинг с HTTPS и постоянным диском. Разворачивайте один экземпляр приложения с локальным постоянным томом SQLite. Для нескольких экземпляров приложения с общей базой понадобится серверная СУБД.

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` для рабочего запуска |
| `TABEL_ORIGIN` | Внешний HTTPS-адрес, например `https://tabel.example.org` |
| `TABEL_DB` | Путь к SQLite (по умолчанию `data/tabel.sqlite`) |
| `TABEL_HOST` | Адрес прослушивания (по умолчанию `127.0.0.1`) |
| `PORT` | Порт (по умолчанию `3000`) |
| `TABEL_TIME_ZONE` | Часовой пояс даты табеля (по умолчанию `Europe/Moscow`) |

Пример для Docker с внешним HTTPS-прокси:

```sh
docker build -t tabel .
docker volume create tabel-data
read -r -s -p 'Пароль кадровика (от 12 символов): ' tabel_password
printf '\n'
printf '%s' "$tabel_password" | docker run --rm -i -v tabel-data:/app/data tabel node src/admin.js hr "Имя Фамилия"
unset tabel_password
docker run -d --name tabel --restart unless-stopped \
  -e TABEL_ORIGIN=https://tabel.example.org \
  -v tabel-data:/app/data -p 127.0.0.1:3000:3000 tabel
```

Прокси завершает HTTPS и пересылает запросы на `127.0.0.1:3000`. Открывайте в браузере и мобильных приложениях адрес из `TABEL_ORIGIN`. Для проверки доступности используйте `/healthz`. Для файловой резервной копии остановите приложение перед копированием тома или используйте механизм онлайн-резервного копирования SQLite.

## Android и iOS

Исходный код отдельного мобильного приложения и конфигурация сборки находятся в `mobile/`. Клиент рисует собственные экраны React Native, в том числе формы ввода, календарь, закрытие месяца и выгрузку Excel через системное меню.

```sh
cd mobile
npm ci
npm run check
```

Эта команда проверяет сборку пакетов JavaScript для Android и iOS. Для локальной нативной сборки Android используйте `npm run android` с настроенным Android SDK. Для локальной сборки iOS используйте `npm run ios` на Mac с Xcode.

Для облачных сборок подключите проект к своей учётной записи Expo. Выполняйте команды из папки `mobile/` в Git-репозитории проекта. Идентификаторы `ru.tabel.worktime` в `app.config.js` замените на идентификаторы, выбранные владельцем приложения, до первой публикации.

```sh
npx eas-cli@latest login
npx eas-cli@latest build:configure
npx eas-cli@latest build --platform android --profile preview
npx eas-cli@latest build --platform all --profile production
```

Профиль `preview` для Android формирует APK для установки на тестовое устройство. Профиль `production` готовит Android App Bundle и сборку iOS для магазинов. Для публикации потребуется настройка подписи и доступ к Google Play Console и Apple Developer / App Store Connect. Введите адрес сервера при входе или задайте его в окружении сборки через `EXPO_PUBLIC_TABEL_URL`.
